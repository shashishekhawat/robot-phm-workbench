How to read this

The top row is the measure worth watching. A thesis stalls by one objective going quiet for months while the others feel busy, so the count is days since anything — a log entry or an experiment — was recorded against each one. The bar turns amber past a week and red past three.

Refutations count as output. An experiment that disproves its hypothesis is recorded, tallied and kept exactly like one that confirms it.

What this is reading

Every row is fetched data, never a placeholder. Deadlines come from each venue's own call-for-papers page; literature is arXiv preprints plus journal articles from MSSP, RCIM, the Journal of Manufacturing Systems, Mechatronics and Measurement. A scheduled task refreshes both each morning at 07:00 IST.

Three things are inference rather than source data: topic tags are derived from each title, preprint months from the arXiv ID, and journal years from the ScienceDirect PII, which encodes a year but no month — those rows show a year only.

Triage is what stops this becoming thirty undifferentiated rows. Mark a paper read or irrelevant, and mark a deadline as one you intend to submit to; only then does the feed tell you anything about your own work.

How this is meant to be used

Filter by what it needs first. Most days you are at a desk, and nineteen of these need nothing else — staring at the robot tasks when you have no robot booked is how a queue becomes noise.

A task marked waiting has an unfinished prerequisite. Click the status to move a task along: backlog, next, doing, done. Estimates will be wrong at first; recording the actual hours is how they stop being wrong.

Question routes

What the threads mean

A question is joined to an objective when some task in your plan says it closes that question and serves that objective. Nothing here is drawn by hand — it is derived from the plan, so it changes as you schedule work.

No route means no task in your plan touches that question. That is the useful column: it is where the plan and the question bank disagree about what matters.

This one is yours to draw

There is no citation graph in the data and I will not invent one, so the threads here are the ones you pull. Switch to connect, click one card then another, and the link records what you think the relationship is. Add notes as pins for conclusions that are not papers.

Free keeps where you drag things. Chronology lays them out by publication date, which exposes what was reinvented rather than built on. Logic stacks them by dependency, so what everything rests on sits at the bottom. Only free mode saves positions.

Suggest links proposes edges from shared tags and dates. They arrive dashed and provisional — keep the ones you agree with, click the rest away. The point is that you decide.

Claims carry an evidence mark: assumed, simulated, bench, validated, contradicted. Adding a claim forces the question the abstract avoids — what was actually demonstrated?

Connect the data repository

—

Your objectives, questions, work log and experiments live as JSON files in a private GitHub repository. This page reads and writes them directly, so every entry you make becomes a commit. Nothing is stored on any server but your own repository.

  1. Create a private repository named robot-phm-workbench-data and push the starter files into it.
  2. Open Settings → Developer settings → Fine-grained tokens and generate a new token.
  3. Under Repository access choose Only select repositories and pick just that data repository.
  4. Under Permissions → Repository permissions set Contents to Read and write. Nothing else is needed.
  5. Set an expiry you are comfortable with, generate it, and paste it below.

Where the token is kept, and what it can do

It is stored only in this browser, on this machine, and is sent only to api.github.com. It is never committed and never leaves for anywhere else. You will paste it once per browser.

Scoped as above it can read and write files in that one private repository and nothing else — it cannot touch your other repositories or your account. If it ever leaks, revoke it on the same settings page and generate another; the worst case is someone editing this log.
